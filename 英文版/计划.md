# 英文版计划：把《达里奥创世录》翻译、配音成英文，上传 YouTube

写于 2026-10-24。这是开工前的规划，各项数字是估算，做完试点短段后再修正。

## 〇、快速路线（10/24 更新，当前执行的就是这一条）

已经拿到原作者授权，目标改为"最快上线"。原作者那里没有无字幕版，所以中文字幕自己抹掉；下面第一到八节的完整规划保留作参考。

| 步骤 | 文件 | 状态 |
|---|---|---|
| 英文译稿（192 条，按中文字幕时间切分） | `translation.json` | ✅ |
| 英文和中文字幕轨（全片时间） | `make_subs.py` → `en.srt`、`zh.srt` | ✅ |
| 抹中文字幕、烧英文字幕、可选换音轨 | `burn.py` | ✅ 合成片段上测试过，等成片做最后核对 |
| 英文配音：按中文起点摆放，和配乐混到 −16 LUFS | `dub.py`（`lines` → `tts_lines.tsv`） | ✅ 流程跑通，等 TTS |
| YouTube 标题、简介、章节、设置 | `youtube.md` | ✅ |

按发布快慢，有三个版本：

1. **原片加英文字幕轨**：上传原片，挂 `en.srt`。不用处理视频，马上能发；缺点是 CC 会和烧在画面里的中文字幕叠在一起。
2. **英文字幕版**：`python burn.py 成片.mp4 out.mp4`。中文字幕抹掉，烧上英文，保留中文原声。处理全片约 15–30 分钟。
3. **英文配音版**：生成 TTS 后依次运行 `python dub.py voice`、`python dub.py mix 成片.mp4`，再运行 `python burn.py 成片.mp4 out.mp4 --audio mix_en.wav`。

## 一、结论先说

- **配乐可以重建**：`声音/` 里的脚本能重新生成整片配乐层 `full-music.wav`（681.67 秒，48 kHz 立体声，不含旁白），10/24 已实测跑通，耗时约 3 分钟。英文配音直接铺在它上面，不用去分离原片的人声和音乐。
- **旁白可以对时**：五章旁白有逐字时码，存在 `数据/chN.js`，一共 53 段、301 条字幕。照着每段的中文时间写英文，长度基本放得下：英文大约 1400–1650 词，读出来 510–660 秒，中文是 623 秒。
- **画面是最大的障碍**：中文字幕烧进了每个镜头，画面里还有大量中文界面字。全片约 40 个镜头，仓库里只有 4 个的源码，单靠这个 fork 做不出干净画面。
- **先联系原作者**：问一下有没有现成的无字幕版。`文档/遗憾与待改进.md` 第二节写着，发布后有人想把片子搬到外网，作者为此把带字幕的镜头全部重渲过，所以无字幕版很可能已经有了。
- **推荐路线 B**：原片画面，擦掉烧进去的中文字幕，换成英文字幕；用英文 TTS 配音，铺在重建的配乐上；关键的屏幕中文加英文注释字幕。如果原作者能给全部镜头源码，再升级到路线 C（画面里的字也换成英文）。
- **先做一段 45 秒试点**：第一章 0–45 秒（开场加"要有光"）。这一段把翻译、配音、对时、擦字幕、混音五件事都走一遍，过了再做全片。这也是原作者复盘里的第一条教训：方向没被小样证明之前，不要扩大制作量。

**原片的声音链**：
1. 旁白每章约 −22 LUFS（`数据/` 里记作 `loudnessLUFS`）。
2. 配乐层整体降 4.49 dB，和旁白相加。
3. 整片做到 −16 LUFS、真峰 −1.5 dBTP，用 4 倍过采样的真峰限制。

英文版照这条链走一遍即可。

## 四、三个硬约束

1. **画面锁定，配音只能将就画面。** 画面事件是按中文逐字卡点的。比如第一章 29.37、30.24、31.12 秒，波长、光强、渲染参数三栏依次出现；第二章 145.59 秒说到"黑洞"时，光子环一亮；第五章四骑士段落里，403、429、402 各在自己那句出现，声音也打在 32.79、38.56、45.31 秒。英文不能只是整段塞得进去，关键词也要落在原来的时刻附近，误差在 ±0.3 秒以内。
2. **协议是 CC BY-NC-SA 4.0**，见 `LICENSE.md`：
   - 翻译和重配音属于改编，协议允许；
   - 必须署名，并注明改了什么；
   - **不能开通收益**（非商业）；
   - 英文版也要用同一协议发布。YouTube 上传时的许可选项只有"标准 YouTube 许可"和 CC BY 两种，**不要选 CC BY**，因为它比原协议宽，违反"相同方式共享"。选标准许可，在简介里写明 CC BY-NC-SA 4.0。
3. **自己的 TTS 也要查条款。** 英文配音是你自己生成的，用哪家 TTS，就要确认它允许把生成的音频公开发布到 YouTube。

## 五、分阶段计划

### 阶段 0：联系原作者，拿素材（第 1 天，可以和阶段 1 同时进行）
- 从原仓库 Release 下载成片和封面。
- 在 B 站 @你好与那啥，或 GitHub `null0526` 上联系原作者，问三件事：
  1. 有没有无字幕版，或者不带字幕的各镜头渲染；
  2. 能不能提供全部镜头源码，以及成片用的英文原文（`方法手册.md` 提到制作目录里存着真实邮件和界面截图）；
  3. 原作者自己有没有做英文版的打算，免得撞车。
  协议本身已经允许改编，但先打个招呼成本很低，也可能直接省掉阶段 4 的大部分工作。

### 阶段 1：45 秒试点（第 1–2 天）
范围是第一章 0–45 秒。英文画面、英文配音、英文字幕、配乐要齐全，最后在手机上看一遍。

这一段要验证四件事：
- **音色**：同一段英文配 3–4 个候选音色，放进画面里比；
- **对时**：英文能不能卡上"要有光"的逐项补参数；
- **擦字幕**：擦完的效果能不能接受；
- **混音**：英文人声和配乐的相对电平。

试点没过，只重做这一段。

### 阶段 2：翻译（第 2–4 天）
1. 写 `make_sheet.py`，从 `数据/` 生成翻译工作表。每一行是一条字幕，包括：
   - 中文原文；
   - 全片起止时间、可用时长；
   - 英文词数预算（按每秒 2.5–2.7 词）；
   - 锚点列（这句话里哪个词必须落在哪个时刻）。
2. 锚点从三个来源汇总：
   - 4 份镜头设计说明里的事件表；
   - 对成片跑 `kit.frame_trace` 和 `kit.spikes`，自动找出切镜、出现、点击的时刻，再对到最近的中文字；
   - 人工看一遍补漏。
3. **按配音的要求翻译**，不是按阅读：句长贴着预算，锚点词的位置尽量和中文对齐。
4. 请英语母语者读一遍，主要看笑点有没有落地。要点见第六节。

### 阶段 3：英文配音（第 4–7 天）
1. TTS 的单位是段，S01–S54 共 53 段，整段生成，语气比按句生成连贯。
2. 用强制对齐拿到英文逐词时间，例如 WhisperX，和原片用的 Whisper 对齐是同一类方法。
3. 写 `build_voice_en.py`，改自 `最小示例/build_voice.py`：
   - 每个子句放到对应中文子句的起点，不再按停顿表顺排；
   - 跟原脚本一样修首尾静音、找段内气口；
   - 输出 `voice_en.wav` 和 `timeline_en.json`，并报告哪些地方超时。
4. 超时的处理，按优先级：先改短文本；再调 TTS 语速，控制在 0.92–1.08；最后才做时间伸缩，不超过 5%。

### 阶段 4：画面（和阶段 3 同时进行）
从好到差有三档：
- **C. 原作者给源码**：所有镜头加 `?subs=0` 重渲，界面字换成英文。最好，但取决于原作者。
- **B. AI 去字幕**：用开源的视频去字幕工具（例如 video-subtitle-remover，基于 LaMa/STTN/ProPainter 修补），只处理底部字幕带。这部片的背景大多是暗色光场、纸面、网页，修补难度不高，但需要逐章检查，尤其是界面元素压到画面底部的地方。需要 GPU。
- **B′. 色块盖住**：在字幕带上盖一条带渐变的暗条。最省事，但比较丑。B 修补失败的个别镜头可以用这个兜底。

**屏幕上的中文字**（计费单、风险台账、工单、邮件等）：
1. 用 OCR（例如 PaddleOCR）每 0.5 秒扫一遍字幕带以外的区域，列出全部屏幕文字和出现时间。
2. 逐条决定怎么处理：
   - 旁白已经说到的：不管；
   - 笑点在字上的：在画面顶部加一条英文注释字幕，比如 `[Billing: geometry · pay-per-call]`；
   - 本来就是英文的：不用动，例如代码、HTTP 状态码、`We appreciate your patience…` 卡片、`Unsupported Region`。

### 阶段 5：字幕、混音、母带（第 7–8 天）
**字幕**：从 `timeline_en.json` 生成英文 SRT 和 ASS（照 `最小示例/make_ass.py` 改）；同时从 `数据/` 导出一份中文 SRT，作为附加字幕轨。

**混音**：
- 0–677.188 秒：配乐层降 4.49 dB；英文旁白每章归一到 −22 LUFS；两者相加。
- 677.188 秒到片尾：直接用成片原声（片尾段应该没有旁白，下载成片后听一遍确认）。
- 整片做到 −16 LUFS、−1.5 dBTP。

**撞车检查**：作曲脚本运行时会打印每个点缀的时间和电平。英文的气口和中文不同，原来放在中文停顿里的点缀，现在可能压在英文重读词上。把两份时间表对一下，列出冲突处，逐个降电平或微移。

**可选改进**：原作者自己说声音偏嘈杂（`遗憾与待改进.md` 第一节），配乐既然重新生成，可以顺手给旁白加自动侧链压低，但这要另外拿样片 A/B 比过。

**片尾**：用一张 HTML 页渲染英文片尾卡，写原作署名、英文版署名和协议，替换中文片尾画面。

## 六、翻译要点

1. **把原本的英文找回来。** 很多笑点本来就是英文产品文案翻成的中文，英文版应该换回 Claude 和 Claude Code 用户一看就认得的原话，不要从中文再译一遍。原文以原作者手里的素材或你自己能看到的真实界面为准：
   - 额度用尽 → usage limit reached；
   - 打开 bypass permissions → 保留英文原词；
   - 每完成一步就点 Approve → 对应 Claude Code 的权限确认；
   - 压缩 → `/compact`；
   - 检测到可疑信号 → 封号邮件里的 suspicious signals；
   - 403、429、402 → Forbidden、Too Many Requests、Payment Required；
   - 申诉被驳回 → 照申诉回复邮件的原话写；
   - 感谢您的耐心与理解 → 黑洞卡片上本来就是 `We appreciate your patience and understanding.`
2. **《圣经》部分用通行英文译本的说法**："And God said, Let there be light"、"God saw that it was good"、the Sabbath、Noah's Ark、the Four Horsemen。英文观众最熟悉这一块，笑点反而更好落地。
3. **中国文化部分要补一句交代**，趁画面在演的时候带过：
   - 后羿 → Hou Yi, the archer who shot down nine suns；
   - 嫦娥奔月 → Chang'e, who drank the elixir and fled to the moon；
   - 祖冲之 → 5th-century mathematician Zu Chongzhi；
   - "那个地区" → 保留含糊，英文观众也能意会。
4. **中文网络黑话换成英文 AI 圈的对应说法**：
   - 降智 → nerfed；
   - "Max 20x 稳定老车，独享车位，翻车包赔" → 写成英文里那种可疑的账号合租广告，例如 shared seat、aged account、refund if banned；
   - 走苹果渠道退款 → refund through the App Store；
   - 伪装干净环境 → 写成 residential IP / clean environment 一类的说法。
5. **语气**：冷静、不加解释的纪录片腔，和原片一致。不要模仿任何真人的声音。
