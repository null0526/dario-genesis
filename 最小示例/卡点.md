# 冷接班卡点清单：《第八天之后：申诉队列》番外粗剪

> 开源版注：本文是制作期间的工作文档，原样公开。文中提到的 `experiments/`、`outputs/`、`production/`、`测试场/`、`留档/` 等路径，以及 D 加数字的决定编号，都指原工作目录，没有随仓库公开；用户原话是作者本人在制作中的反馈。

执行者：冷启动的 Claude Sonnet 5.5。只读了：方法手册、工具索引（全文）、质控正文、声音点缀做法、ch5-appeal / newton-notice / god-console 三份母版 README，以及索引点名的脚本 `tools/openrouter_audio.ps1`、`read_speech_timing.py`、`check_film_quality.py`、`score-claude/kit.py/synth.py/mix_sample.py`。
实际耗时：约 15 分钟墙钟（系统时钟 12:58 到 13:12），远小于 90 分钟时间盒。成片 74.9 秒，247 个汉字旁白，4 个镜头，9 次 TTS 共约 0.05 美元（前三条收据 0.0028、0.0062、0.0024，其余按字数估）。

产出（都在本目录）：
- `第八天之后-申诉队列-粗剪.mp4`（1920×1080 / 30fps，−16.0 LUFS，−1.7 dBFS 峰值，解码无错误，无黑场）。`pre-master.mp4` 是未过限幅的版本。
- 过程脚本：`script.py`（分段文稿）、`make_requests.py`、`build_voice.py`、`shot.html` + `render.py`、`sound.py`、`make_ass.py`、`sheet.py`；`cues.md` 是声音点缀表。

## 一、缺信息（手册没说、指向文件也找不到，我自己猜）

**M1. 世界观没有速写。** 流程第 0 步（开工）。手册和质控正文只零散提到“第七天、额度、申诉、办事处、平台”，没有一页说清这个世界：谁是平台、人类处于什么位置、第七天以后发生了什么、哪些梗用过。我猜：平台是 ANTHROP\C，创世是“七天施工”，人类在第五章已经提交过申诉（来自 ch5-appeal README 的零星线索），第八天是申诉的起点。写番外时最怕撞已用的梗，但我无从核对。建议：手册第三层开头加“世界观速写（5 行）+ 已用过的包袱清单”，或点名一个 1 页的文件。

**M2. 旁白字数与时长的换算没写。** 写文稿时。我按 250 字写，配音出来 64.8 秒纯语音，加气口、停顿、片头片尾共 74.9 秒，超过“约 1 分钟”。建议手册第 4 条加一句：“minimax doc_commentary 约 3.8 字/秒（含句间停顿），写稿时按这个估时长；1 分钟约 200 字”。

**M3. 最小 TTS 请求 JSON 长什么样，索引 W2 没给。** 配音第一步。索引只给了命令和 `S34-request.json` 的路径，我是去读那个文件才知道 `model/voice/input/response_format` 四个字段。还有：路径必须在项目内、参数相对路径以项目根为准（不是 cwd）、输出已存在就拒绝。建议 W2 里直接贴一个四字段示例 JSON，并写“`-RequestFile`/`-OutputFile` 相对项目根，不是当前目录”。

**M4. 没有“把分段 mp3 拼成连续旁白并生成字幕分块时码”的通用做法。** 配音后、对齐前。T3 绑死章节和 PAUSES 表，T2 绑 Whisper snapshot 和第五章 spec。我自己写了 `build_voice.py`：解码、削首尾静音（阈值 0.004）、按停顿表拼接、用段内静音吸附加字数比例推字幕分块时码，约 80 行。我猜的参数：句后停顿 0.4–1.0 秒（笑点前 0.8）、片头 0.9 秒。建议索引在 T3 之前加一条“T0：新片最小旁白拼接模板”，指向类似的脚本，并写明停顿表怎么定（例如“笑点和转折前 0.8–1.0，承接 0.4”）。

**M5. 世界观里的品牌使用边界没交代。** 画面设计时。newton-notice README 给了 B 类网页参数，我照用了 “ANTHROP\C” 字标和 AnthropicSans 字体做画面。但手册第三层说“下一部片不应默认沿用本片品牌”，质控又要求“全篇 anthropic 风格”。番外算不算“同一部片”？我猜算，沿用。建议第 14 条风险清单旁加一句“番外/续作沿用字标的规则：沿用 / 需另询”。

**M6. 番外要不要先过“20–40 秒完整短段”（第 2 条），手册没分档。** 开工第一步。冷接班下没有用户可看，我直接做了全片（只有 4 个镜头、同族的 A/B 两类界面）。我猜这满足第 2 条“已认可的同类表达可以跳过”。建议第 2 条补一句“≤90 秒、全部画面类别都已有认可母版时，整片即可当短段”。

**M7. 质控检查工具对番外怎么用没有说明。** 交付前。`check_film_quality.py <目录> --stage publish` 返回“没有本候选的实际审片采用记录”。`quality-review.json` 的字段（decision / scope / review / evidence）在手册和索引 Q1 里都没写，我读了脚本才知道要这些键。我没有伪造“通过”，因为这既不是我能判的、手册也明令不得虚填。建议索引 Q1 贴一个空模板 JSON，并说明“冷启动模型没有用户审片时应当停在‘待用户审’，不填 proceed”。

**M8. “字体可复制范围”没说。** 做字幕时。第 7 条说“系统里的商业字体不能复制分发”，但没有列哪些可以。我把 `NotoSansSC-VF.ttf`（索引 F1 写它是 Noto Sans SC，SIL OFL 开源）复制进了本目录 `fonts/` 给 libass 使用，没有对外分发。拿不准是否在边界内。建议索引“中文字体”那一行直接标“Noto Sans SC：OFL，可复制；华文中宋 STZHONGS：系统商业字体，不可复制”。

## 二、工具故障（照索引命令跑不通，或结果与说明不一致）

**F1. T1 `read_speech_timing.py` 对中文几乎不可用。** 对齐步骤。命令 `.venv-voice/Scripts/python.exe tools/read_speech_timing.py <in> <out> --language zh` 能跑（4 秒，不联网），但对 S01“第八天，人类的申诉进入了队列”输出“第八天,人位的生速進入了對列”，含繁体和错字，时间戳只有整句级。索引的说明“会有同音字”太轻了，实际是不能用来核字、也不能做字级时码。处理：不用它，改用静音检测 + 字数比例（M4）。建议 T1 的局限一栏改成“base 模型对中文输出繁简混杂和大量错字，仅可当有无语音的 VAD 用；字级时码必须用 T2 的约束对齐，新片需要先改成可传入文稿的通用版”。这也意味着手册第 5 条“对齐后输出锚点”在冷启动下没有现成工具，是最大的缺口之一。

**F2. 路径回显乱码。** TTS 与 Python 回溯里，含中文的路径在 Git Bash 里显示成乱码（一串问号和怪字符），但文件实际写对了，请求也成功。我一度怀疑路径没写进去。建议索引 W2 加一句“输出的路径回显可能是乱码，以 ls 为准”，Python 调用时统一建议 `export PYTHONUTF8=1`。

**F3. 环境提示与 `-I` 冲突，ffmpeg 不支持 glob。** 小问题：①按“用 `-I` 运行 Python”的惯例跑自己的脚本会找不到同目录模块（索引没提，因为它只管项目脚本，非手册问题，记作提示）；②`ffmpeg -pattern_type glob` 在这个 gyan 构建上不可用，做声音做法里“联系表（fps=1,tile）”时不能用 glob。手册没有联系表脚本，我自己用 Pillow 写了 `sheet.py`。建议索引补一个 `tools/contact_sheet.py`（任意图片目录或视频 + 间隔 → 联系表）。

## 三、判断不足（信息有了但拿不准）

**J1. 听不了声音，音色、读音、语气都没法验。** 配音之后。手册第 11 条已写明 AI 不能听，我照做：只测电平和 ASR。ASR 又不可用（F1）。我避开了读音坑（“一行”“还给”，改写时没有用“还”和“行”），但“重复（chóng）”“为（wéi）”“会儿”是否读对完全未验。建议第 11 条补一句最小自检法：把易错字集中成一条 3 秒测试句先配一次，由用户或能听的模型听；或者写稿时在“稿件风险字表”里先把多音字全部换掉。

**J2. 笑点是否成立。** 文稿。我的包袱是“七个工作日”→“平台从没设过工作日（创世前六天叫施工、第七天叫休息、第八天没有名字）”，结尾是“人类回复了”→自动回复“已加入队列，排位 7,980,000,001”。我觉得结构是从容纪录片腔 + 冷结尾，符合第 18 条，但“排位第七十九亿”这个数字在语音里很长（约 3.5 秒），可能会拖慢节奏。拿不准。已记录，建议成为用户 A/B 的一个问题。

**J3. 画面是否撞质控第 5 条（停留要有可看的过程）。** 采用判断。场景 D（邮件）整屏下半部分空白较多，场景 A 的点阵每点 3 像素，在 390px 宽时几乎看不见点，只剩灰块。质控第 3 节 A 要求“实际观看尺寸下看整段、390px 检查”，我只抽了 6 帧缩到 390 宽看，点阵确实糊成灰块，但数字和字幕可读。我没有再做修改，记为“未证实”。建议质控或手册配一个“代表性帧 6 张 + 390px”的标准动作模板，并说明哪些问题算返工（例如“点阵小于 8 像素在手机上视为不存在”）。

**J4. 画面好不好看，完全无法自评。** 质控第 3 节 A 要求“协调者亲自打开实际产物”，我只能看抽帧。UI 类画面（A/B 类）本来就是“像真产品”，美术空间小，我照 newton-notice 的 B 类参数（`#f4f3ef`、`#d97757`、圆角 12–18、柔阴影）做，自评“通过七条淘汰线中的大部分，但整体偏模板、缺一个有力的视觉事件”。最有力的是“0 / 7”红字、工作日被划掉、诗被切断的下落。建议质控补一句“代码做 UI 类镜头时，每镜至少要有一个有后果的视觉事件，写进镜头清单”。

**J5. 母带规格选哪一档。** 混音。手册第三层写 −16 LUFS / −1.5 dBTP，工具索引 M2/M3 的自写母带又绑死本片（5 个章节、旧哈希）。我直接用 ffmpeg 一行 `volume=0.8dB,alimiter=limit=0.82` 加 `ebur128` 复测，得到 −16.0 LUFS、−1.7 dBFS（采样峰值口径，没有做 4 倍过采样真峰测量，ebur128 的 `peak=true` 给出的是真峰 −1.7）。我判断一分钟小片不必抽取母带模块。建议索引 M3 末加一行“≤3 分钟的短片：直接用这条 ffmpeg 两步（命令如上），不必走 mix_r5”。

**J6. “静默是工具”到底该在哪抽空。** 声音。声音做法写得很清楚（循环、让路、一章一口钟），我照做，把全片唯一的教堂钟放在最后“自动回复出现”之后，然后静默 5 秒。但我无法知道这个冷结尾是否过长，也没法听钟声和旁白最后一个字是否打架。建议第 18 条“包袱前抽空”的“还没验证”再加一句“结尾静默时长上限：冷结尾 ≤ 4 秒，除非有视觉事件”，让下一位有数字可对。

## 四、手册说得清楚、照做就成功的地方

1. **第 5 条（画面绑旁白锚点）有效。** 我先把 `timeline.json`（各分块起止）生成给 `shot.html`，所有动作读锚点。中途改了三次画面和字幕尺寸都只需要重渲（56 秒），没有重新设计动作。
2. **第 6 条（声音和画面同时起步）有效。** 声音脚本直接读同一份 `timeline.json`，点缀时刻写成“某分块起点 + 偏移”，一次对位无误（以逻辑和 cues 表核对，未听审）。
3. **声音点缀做法：电平口径和让路规则可直接执行。** `kit.make_place` + `level_bus` 的 rel 表可以直接套；“循环在重拍前压低 7 dB”照 ch1 脚本写法实现；“一章一口钟、循环 tapestop 切断”也有现成函数。最后 `peaks_per_second` 无超 1.6 的秒。
4. **第 10 条“先自己清客观错误”。** 我清了：字幕盖住后台列表（因此把列表裁到 y<890）、字幕在 390px 太小（46 改 62）、“创世日历”标签压住大数字（删除）。三处都是抽帧检查发现的。
5. **质控第 4 节“先看实际观看尺寸”。** 帮助我发现了字幕太小。
6. **B 类网页参数（newton-notice README）。** 色值、字体、圆角、阴影的清单可以照抄，是整套材料里“最直接可用”的一页。
7. **索引 W2（TTS）。** 照命令跑一次成功，9 段共 40 秒内完成，收据与 `-UsageReceipt` 查费用正常。凭据完全由工具处理，我没有碰。
8. **质控 D 项（技术可用）。** 解码、黑场、响度都可以用一条 ffmpeg 命令测。

## 五、建议手册怎么改（汇总，按价值排序）

1. 在手册开头加一页“**冷启动 12 步清单**”：读世界观速写 → 写稿并估时长（3.8 字/秒）→ 写 TTS 请求 → 配音 → 拼旁白 + 分块时码 → 画面骨架（`shot.html` + `render.py` 模板）→ 声音脚本 → 字幕 ASS → 合成 → 母带一行命令 → 抽帧 + 390px 自查 → 写交付说明。现在手册是原则式，新模型得自己拼流程。
2. **补两个小模板进工具索引**：①最小旁白拼接 + 分块时码（M4）；②最小 Canvas2D 渲染骨架（`window.grab(i)` → JPEG → ffmpeg pipe，约 50 行，我的 `render.py` + `shot.html` 可作原型）。V1 的描述对新手来说太散，各母版 render.py 不一致，我没有读也无从复用。
3. 索引 T1 把“局限”改成“中文基本不可用，只能当 VAD”，并明确新片字级对齐的缺口。
4. 手册第三层“Chrome 不能写中文路径”：**实测不成立**。我在中文路径目录用 Playwright + Chrome 155 `goto('file:///…中文路径…/shot.html')` 加载成功，读字体 `../../../references/…` 相对路径也成功；写文件由 Python 完成，没有碰过这个问题。建议改成“某次命令行截图的 Unicode 路径在 shell 链中失败，经 Python/Playwright 管道写文件不受影响”，与索引 P1 的口径一致（凭本次依据推翻，修订记录里追加一行）。
5. 第 7 条“独立字幕层”：我用 ASS + libass 实际做成了，纸面/暗底各一个样式（亮底墨色 `#26221c`、暗底 `#e9e6df`，62px，无描边），整体可行；字幕样式表和字体目录可作为小样模板收进索引 F2，同时记录“46px 在 390 宽看不清，下限约 60px”。
6. 在质控或手册加一句“**番外/续作的复用范围**”：品牌、世界观、已用包袱、字体授权（M1、M5、M8）。

## 修订建议备注（不改手册，按冷接班规则只写在这里）
